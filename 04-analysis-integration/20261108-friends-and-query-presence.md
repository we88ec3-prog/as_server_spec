# Server好友名單與查詢式在線狀態

2026-11-08。關聯A-014與F17，延續[聊天拒收](20261108-chat-ignore-and-native-blacklist-boundary.md)。使用者要求持續完成Server功能；本輪好友名單、單向關係、容量、查詢式狀態與操作限制全是**Server重建政策**。沒有新增原件證據、原生FriendDialog wire、雙向同意或SDK相容的完成宣告。

## 功能與原生界線

原版社交／地址簿仍依[既有契約](../02-server-planning/social-contract.md)與[郵件／NMCO界線](20261108-native-mail.md)追查。本輪不把C12/S58泛稱好友增刪協定，不拿原生本機黑名單20格當好友資料。已辨識C12地址簿請求沿用既有提示，未填造列表回覆，原FriendDialog與NMCO均未接線。

替代操作使用已證C0E(kind0)普通聊天輸入與S0A17／18回覆。命令大小寫不敏感：

|指令|操作|
|---|---|
|`/friend add 角色名`|加入本人的單向收藏名單，可加入離線既存角色|
|`/friend remove 角色名`|移除本人名單中的角色|
|`/friend list`|查第1頁與目前可聯絡狀態|
|`/friend list 2`|每頁10筆，頁數1..10，超出目前頁數提示|

每名角色最多100個好友，與100人拒收名單分開計算。單向收藏表示A加入B不修改B的名單、不發邀請、不取得B同意，也不通知B。這不是已證原服關係模型；互邀／同意制若後續要做，需另立規則，不能把本版收藏當雙向好友。

命令只回本人，不作附近聊天，不增加聊天成功發話額度。操作結果用S0A17短提示；列表用S0A18聊天歷史，含總量／頁碼與角色現名。列表不展示內部ID、帳號、地圖、座標、裝備或私訊內容。kind2技能文字不會被當好友命令。

## 保存與所有權

本人需當前完整World租約、已提交載圖，舊連線／錯account／pending載圖不得讀改。target以嚴格CP950最多24bytes、非空且無控制或空白字元驗證；NFKC＋InvariantUpper查權威角色名。不能加自己、不用帳號名冒充角色名。目標可離線；未知角色明確回InvalidTarget。

關係保存owner character ID與target character ID、加入UTC時間；查詢讀現名，不因大小寫產生兩份關係。每owner有獨立單調revision；新增實際關係或移除實際關係加1，已存在再加／已不在再刪為NoChange不加版。revision溢位拒絕。修改帶expected revision，競爭只允許一位勝出，失敗者重查。

好友不授予私訊、隊伍或交易權限，不影響傷害／獎勵／資產。移除好友不自動封鎖私訊，不退隊，不清拒收；加入好友也不解除拒收。100個好友與100個拒收可同時存在。名單跨離線、重新登入與Server重啟持久保存。

## 可聯絡狀態

每次list重新查當前World連線：具精確當前租約、已提交載圖且沒有pending載圖才算在線，跨地圖不影響。只建立登入／載圖中、結束World或離線都不算。新租約重新載好圖可再次顯示，不能憑舊連線快照一直顯示在線。

若owner拒收target或target拒收owner，顯示與離線相同的「不在線／不可聯絡」，不透露哪一方封鎖。關係仍保留，解封後重新list才顯示現在狀態。只有真正可聯絡者顯示「在線」。這是拒收的重建政策，不是原件privacy選項證據。

狀態只代表查詢期間觀察，不保證後續密語送出時對方仍在線。真正密語仍重新執行既有權威投遞檢查。每次查詢最多100名、有限處理，不持久存online布林，不從操作回執回放過期presence。CheckedAtUtc是查詢完成時間，非全世界同一瞬間的租約凍結。列表未做自動在線／下線推送，需再次list更新。

## 交易與重送

owner租約→party gate→chat gate，與拒收修改共用序列化邊界，不反向鎖target租約。名單、revision及操作回執同交易。任一項失敗整體回滾，不出現關係已刪但revision或回執未保存。

命令意圖含正規化target、Added及expected revision。相同operation ID及相同意圖在2分鐘內回原結果，不重新套用；同ID不同意圖拒絕。故舊新增重播不能把後來刪除的人重新加回。結果只保存操作revision／outcome／名稱，不保存online；presence必須另查。

每角色最多128筆活回執，達上限暫拒修改（包括刪除），到期後重試，不提早逐出舊回執。非法目標或滿名單不保存新回執；Applied與NoChange保存回執。Host每次命令產生新內部ID，原生C0E沒有永續操作ID，兩分鐘後不保證同ID防重。正常查列表不占修改回執。

## 遷移與驗證

新增friend_state、friends及friend_ops三表。owner／target FK、owner!=target與複合主鍵保護；既有有帳號SQLite建缺表前一致備份，獨立tag `.pre-friend-list-v1-*`，暖啟動不重複。舊帳號、金鑰、聊天、拒收、道具與角色進度不重寫。PostgreSQL有等價DDL與鎖路徑，實例和完整還原另驗。

完整986項.NET回歸通過（0失敗／0略過）。定向11項新增Store／Host驗證涵蓋單向／離線／保存、目前在線與pending載圖／換圖／斷線／新租約、雙方拒收遮蔽、重送／revision／所有權、刪除回滾與競爭、回執上限到期、備份內容及命令私人投影。並擴充既有100人容量情境，同時驗兩種名單各100且互不占額。

三個獨立合成Client的真TCP六組情境通過：私人單向增刪／列表、目標拒收遮蔽、本人拒收遮蔽、斷線及新World租約的目前狀態、自己Host重啟後保存，以及解除好友後普通密語仍可送達且第三人不收到列表。測試Host SHA256 `e997e37acfd5eb761100ef0d45016059a94d4637d0932e33d8fae9041714cf57`。只重啟自建隔離Host，未動使用者Client／Server。

原生FriendDialog／GUI未測，不能將聊天命令和合成流程當原介面驗收。互邀同意、主動狀態推送、原生地址簿同步、NMCO、公會及完整社交設定仍需後續完成。
