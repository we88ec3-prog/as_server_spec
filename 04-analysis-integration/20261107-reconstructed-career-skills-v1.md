# 七職業重建技能第一版

2026-11-07。來源分開：使用者要求先交付可調整的重建技能版本，並擴及騎士與吟遊詩人等進階職業；下列技能名稱、等級、熟練度、消耗、傷害、冷卻及自補規則都是 **Server設計**，不是找回的原服技能表。原生S62／C0E／C65提供相容入口，不能反過來證明這些重建數值是原版。

目前已核對並啟用的七職業各有三項、共21項。這是共同近身動作的可玩測試子集，**魔法師的法擊、吟遊詩人的音擊也仍是近身測試版**；沒有把共用出拳投影稱為原版遠程法術、歌曲或完整職業技能還原。

使用者指出的**預言者、阿修羅是職業名稱**。本版Client是否含其完整資料、可用編碼、轉職條件與技能，保持「職業支援待確認」；不得由目前已核對的1..7碼逕自排除，也不得猜成8／9直接下發。

## 內容與調整方式

[完整機讀平衡表](reconstructed-career-skills-v1-20261107.json)記錄每項穩定key與三個rank的精確值。本版Revision為 `reconstructed-career-skills-v1`。

|---|---|---|---|---|
|戰士|重建重擊／重建迴旋斬／重建調息|0／10|0／15|5，補15|
|盜賊|重建迅擊／重建迴旋刺／重建匿息|0／8|0／12|6，補12|

- 單體取權威面向的相鄰一格；範圍取自身切比雪夫距離一格內、最多八個存活怪物。沒有依滑鼠位置、Client傳入傷害或任意object ref選取目標。
- 單體冷卻1000ms，範圍1800ms，自補5000ms。攻擊技能還與普攻共用既有最短命中間隔，不能在兩種入口間切換繞過。
- 自補恢復的是HP，不是防禦BUFF。未證持續效果的時間欄位前，不偽造S2C持續效果包、倒數圖示或防禦數值。
- 傷害為rank基礎值加職業指定能力除數，取整數後按目標剩餘HP截頂；能力種別與除數見機讀表。自補不使用該能力加成。
- 平衡值必須與revision一起調整。相同revision配不同內容會拒絕啟動該次操作；新revision可更新平衡而保留學習slot、累積成功次數及既有冷卻，不因調參重置角色。刪除已學技能要另做明確遷移及原生移除清單驗證，不能靜默搬動slot。

## 習得、rank與資源

本版沒有假造技能書購買或另一種技能點貨幣。角色為權威職業且達到門檻後自動取得：單體Lv1、自補Lv2、範圍Lv3。選職、角色等級與技能狀態皆由Server讀取，不接受C0E字串替玩家更換職業或學習技能。

rank2需要累積10次成功使用，並分別達單體Lv5、自補Lv7、範圍Lv8；rank3需要30次及Lv10／12／15。rank1／2／3的累積門檻是0／10／30，不是每次升級後歸零。一次範圍攻擊無論命中幾怪只增加一次熟練次數。失敗、空揮及滿血自補均不累積。

rank2的非零MP成本增加1、非零SP增加3；rank3分別增加2／6。攻擊power比rank1增加3／6，自補增加7／15；各rank仍維持原技能冷卻。這些數值可更換，不代表原服學習或熟練度公式。

沒有怪物時仍可由Host投影空揮，但不扣MP／SP、不啟動該技能的遊戲冷卻、不給熟練度、經驗或任務進度。滿血自補不扣MP；不足資源、死亡、未學、錯職業、舊World lease或位置版本衝突，不產生半次效果。正常空揮的視覺防連發另由Host限制。

## 持久化與交易合約

1. 穩定Server skill key、原生kind／slot、icon frame與CastValue是不同身份。kind1／slot1保留既有普攻；新技能從2..80配置空slot，學習與catalog重排不改動既有slot。icon18只是已核對的共用拳頭影格，不能當技能ID。
2. 下發S62前核對已學清單。這版使用已證的noncast mode5、CastValue0與固定命令文字；C0E執行後的C65只是使用後續通知，不能第二次扣資源或傷害。
3. 每次Server接受的意圖有內部operation ID。操作receipt綁角色及canonical command，重放回原收據、不重做傷害、經驗、資源或動畫；同ID改內容會衝突。Client本身沒有這個nonce，不宣稱能識別所有玩家刻意再次按鍵。
4. 資源扣除、範圍內各怪HP／重生狀態、命中紀錄、每殺預設50經驗、技能熟練度與冷卻，以及操作receipt在**同一資料庫交易**內提交。後段寫入失敗會整筆回滾，無需再補一筆容易重放的「退款」操作。熟練與成長政策的revision都要核對。
5. 內部status revision可能因扣資源、回復、經驗分別前進數次，但只一次交易提交。不能假定每個技能只讓status版本加一，或將舊收據狀態覆寫最新狀態。
6. 原生效果與S08資源投影由Host輸出，致命命中仍沿既有S13後的死亡呈現窗口。不得因資料庫已提交就立刻移除尚在播放受擊數字的物件。

沿用Client SHA256 `db3df616f68b9f32163abc4b88de9d310562b2ddfe955aaa5ba7fcff729e1145`。本輪根據既有與新REA視圖補查：

- `0x46d2c0`（`ev_898408280f6cdda18d2177718a734a50024b484637ea629c74c8a0407c101b3a`）讀entry+7使用方式；mode5呼叫0x401ed0，其他模式有選取分支。不能把mode0當成可執行預設。
- `0x4f2cd0`（`ev_28650859ae46779c32f71804bd31a1c6240c5b32c283ecf9f7a4f48f9ccde354`）接S62後會先以第四段字串查HelpString metadata，再建立ActionEntry；不是本機完整戰士技能表。metadata缺件的影響需與能力窗調查整合。
- 本地Script資料夾316檔作有界zlib／UTF16 XML與literal搜尋，315解析成功，`NDW.dat`不符這個wrapper而保留未查。範圍內命中的職業與技能文字主要是職業介紹、操作說明、Server參數及回城書提示，沒有得到可用的戰士技能ID／等級／成本清單。這個有界陰性結果不代表整個Client必定沒有其他技能資料。
