# 實機Map7畫面錯位：S04相機偏移修正

日期：2026-11-01。使用者完成部分完整路線測試後回報異常，提供畫面並指出
「地圖看起來與實際位置不符」。畫面顯示座標30,34，但大部分場景為黑色，
建築偏到右下。這是診斷Client實機失敗證據，不是原版地理身份確認。

## 核對結果與原因

本地Server紀錄顯示入學轉Map7的C35已處理成功，且已發S04／S33及五個場景
物件；持久角色位置為Map7、30,34、面向2。沒有用重建角色或換地圖迴避此問題。

錯誤在Server開發工具產生的候選內容：將ViewportX設為SpawnX-8、ViewportY
設為SpawnY-6，即Map7的22,28。這兩欄沿用舊命名，但S04實際上需要角色與
視角之間的格偏移，不能填入絕對地圖左上座標。

[既有原生相機分析](appearance.md)的公式：

`origin=((x-vx-1)*48,(y-vy-1)*32)`

`anchor=(x*48+24-originX-56,y*32+16-originY-36)`

|Map7設定|角色world XY|S04 vx,vy|推導螢幕錨點|
|---|---|---|---|
|錯誤generated v1|30,34|22,28|1072,908|
|修正generated v2|30,34|8,9|400,300|

錯誤設定較正確錨點偏右672、偏下608pixels，能解釋畫面與座標顯示分離。
根因是本地復原版設定產生錯誤，不是這次證明了Windows更新或原Client缺陷。
本輪不改world XY、面向、地圖檔、圖塊索引或Client EXE。

## 修正與現有進度

完整候選產生器的六張AdditionalMaps統一使用此Client profile已分析的8,9，
profile ID改為`isolated-tutorial-route-candidate-v2`。Map6原本就是8,9。
S04 wire欄位與既有配置key保留名稱ViewportX/Y以相容，文件明確說明為偏移。

現有完整路線入口只對**逐欄相同的已知generated v1模板**進行修復：

1. 先驗JSON schema／重複key，再由相同Client素材生成預期模板並比對全部內容。
2. 比對相同才先複製完整原檔為獨立backup，再以新暫存檔原子替換profile。
3. 僅改profile ID與視角欄位。DB、帳密、Admin key、角色、入學事件不修改。
4. 自訂過的v1拒絕自動覆寫；backup失敗不覆寫；已修正v2不重寫、不重產。

此機器已備份並修復本地完整路線profile。v2檔案SHA為
`89d82bc619c4ab6934198787f9fbd43d536af2413fcd3ef419366eeb05450bef`。
檔案含本機素材路徑，其他機器應記自己的SHA，不硬套該值。
執行中的Server已讀入舊設定，不會因修改檔案自動熱更新。需停止該測試Server
並重啟同一固定環境；既有角色重登直接從已提交的學校位置接續。

## 驗證與尚待事項

四項Python遷移測試通過：精確模板backup／替換且其他檔不變、自訂模板拒絕、
v2冪等、backup失敗不寫原檔。未改.NET業務程式，既有353項測試基線不變。

完整TCP工具補上獨立相機公式斷言，逐個S04要求8,9且錨點400,300；不再只
檢查前四bytes的角色位置。用舊backup跑負向測試，精確失敗在此斷言；用v2
跑五職業完整流程全部通過，含學校／城鎮重登、職業與ordinal。

先前TCP「全通過」未覆蓋相機欄位語意，因此不能推論GUI正確。本次補齊該
缺口仍是Server／數學驗證；實際Client居中、NPC可見及後續流程待使用者復驗。
正式Native CT與整體目標保持未完成，不因設定修正直接標通過。
