# 正式隊伍與最高總傷害獎勵

目標來源是使用者 R-033：**最高隊伍總有效傷害勝出，該隊全員各得完整基礎 EXP，各人獨立判定完整掉落表**，其他隊伍不得因最後一擊得獎。本輪取代先前 solo 開發 fallback 與最後一擊 EXP。原生線路見[REA 組隊證據](20261108-native-party-membership.md)；以下 tie、名冊時點、離線與跨圖資格、管理命令等為明示 Server 重建政策，不冒稱原服規則。

## 成員權威與同意

角色只能有一個有效隊伍。隊伍保存穩定 ID、隊長、名冊版本及成員；邀請不是入隊，必須由受邀角色的目前精確 World 租約同意。邀請保存 ID、當時隊伍版本、邀請者 ID／姓名、受邀完整 account／character／generation／connection、期限及狀態。同一受邀租約同時僅有一個有效邀請，期限 10 秒，與已證原生邀請視窗時限對齊。

接受時再核對目前租約、邀請狀態／期限、隊長及隊伍版本、接收者尚未入隊、容量；舊邀請、換連線、拒絕或重送不能再次加入。管理操作需預期名冊版本與內部操作收據；同 ID 異命令拒絕。隊長可邀請、踢其他成員、移交隊長或解散；非隊長不能冒名。隊長離隊時依剩餘角色 ID 字典序選繼任者，為本輪重建政策。

容量上限採已證 Client 名單可顯示的 **13 人含自己**，不聲稱這就是原服 Server 限制。離線保留成員，重新登入恢復隊伍；線上連線租約仍照既有 EOF 精確清理。名冊／隊長、姓名、職業、HP 與線上狀態須從同一一致快照投影，不能兩次讀取撕裂成「隊長已不在成員中」。

## 原生邀請與名單

| 封包 | 支援內容 |
|---|---|
| C2E op0 | `0,string8目標角色名稱`，邀請；若自己尚未建隊可先建立單人隊伍，不自動加入接收者 |
| C2E op1 | `1,string8邀請者名稱,u8接受,u8alternate`；本輪只接受已發出的正常邀請 alternate0 |
| S3A type4 | 邀請者名稱，開原生接受／拒絕視窗 |
| S3A type0 | 追加其他成員：ref、職業、HP百分比、名稱；Client 空名單自動插入自己，不送 type0自己 |
| S3A type1／2 | 移除 ref／指定隊長 ref；type1自己可清空名單 |
| S3A type3／6 | 指定 ref 的 HP百分比／職業局部更新 |

type0 不去重：成員／姓名變更先以 type1自己重建，再追加其他人與隊長；只有 HP／職業變更時發 type3／6，不能每次輪詢追加整隊。會員引用為持久唯一 u32 `0x10000000..0x1fffffff`，每位接收者的自己映為 1；與目前怪物、NPC、地面引用分離。

GroupMemberDialog 可單獨以名單資料顯示，不必先在世界生成該玩家。**本輪不代表完整多人角色外觀或跨圖對隊友施法已完成**。離線成員以 0%HP 保留姓名／職業，這是重建呈現，不是已證獨立原生離線旗標。

C2E 回覆沒有 invitation ID 或 nonce，Host 必須以本連線已發邀請、姓名、期限及內部能力綁定，不能讓 Client 選任意 party ID；也不得宣稱能區分無法由 wire 區分的跨輪同姓名回覆。C12 包含好友、公會、郵件等分支，不能拿未知 sub 當組隊操作。

## 可操作的 Server 管理命令

普通聊天 Enter 已證會送 C0E kind0。尚未找到原生離隊／踢人／移交／解散 producer 的完整閉環，因此本輪使用明示 **Server 新增** 的命令，不改主程式、不捏造 C2E op2：

- `/party create` 建隊；`/party invite 角色名稱` 邀請，對方仍須同意。
- `/party leave` 離隊；`/party kick 角色名稱` 踢人。
- `/party leader 角色名稱` 移交隊長；`/party disband` 解散。

回饋用已證 S0A type17：`u8=0x11, CP950位元組數:BEu16, CP950 bytes`，無 NUL、不是 UTF16LE。原生顯示三秒短訊息，與 S02 重建登入／遊戲 UI 無關。本輪回饋文字限 255 encoded bytes；未承諾聊天記錄長期保存。一般聊天／密語／好友、公會及尋隊列表仍是另行功能，不因這些命令標為完成。

## R-033 傷害歸屬與唯一死亡結算

每筆正的實扣 HP 傷害，在同一怪物變更交易記錄當時認證的 party ID／版本；無隊伍為一人隊伍。每個 party 對該怪物生命首次有效命中時凍結全名冊，之後入退隊／解散不回寫這份獎勵名冊，不能將現在的組隊關係套給以前傷害。

按同一 map／內容版本／出生點／生命序號累加隊伍有效傷害。死亡只選一次最高總和隊伍；同分依最早有效傷害版本、再 party ID 決定。獲勝凍結名冊的**每個人**均取得完整基礎 EXP，包含沒有輸出、已離線或跨圖的成員，不能縮成有貢獻或距離內的人。這些 snapshot／eligibility／tie 為本輪政策。

死亡交易同時寫不可變結算證明與每角色唯一 entitlement：基礎 EXP、成長政策快照、每項掉落抽值／結果及私人地面物品。掉落表支援最多 32 項，每人每項獨立抽值，未中也保存結果；重登／重啟／重播不能重新抽，也不能讓最後一擊者領到其他隊的物品。預設仍是重建 HP藥水1／100%，可配置多項及機率，原服掉落表未知。

跨角色 EXP 不在持有怪物／隊伍鎖時另拿其他人的連線鎖。死亡交易先永久確立全員權利，再由本人登入或在線輪詢時，在精確租約交易中套用 Pending EXP、能力版本及 Applied 收據；每批最多 64 筆，斷線後繼續補領，不重複加經驗。最後一擊者沒有額外一筆舊流程 EXP。正 EXP 缺少成長政策屬無效配置，最早入口就拒絕，不能靜默改成 0。

已開始正式結算的怪物生命固定其完整政策；同生命不能改表、改經驗或關掉正式模式退回最後一擊。升級前未分類舊傷害只能明示回補為 `LegacySoloSnapshot`、保存原事件／實扣／版本；這不是恢復了歷史 party，不能用目前名冊填補未知。

## 保存與限制

新增隊伍 gate、狀態、單一成員歸屬、邀請、操作收據、成員引用、怪物隊伍傷害、凍結名冊、死亡結算、個人 entitlement 共 10 類資料；World 輔助表檢查 38→48。SQLite 既有角色庫先一致備份一次，再建缺表，保留原角色／物品／地面／進度。

領取失敗回滾不能部分加 EXP 或部分標 Applied；死亡失敗則怪物 HP、傷害、技能消耗、結算、掉落與收據全部回滾。私人地面仍使用已完成的 canonical 物品保管與領取競爭。引用耗盡保留 `ReferencePending` 證明，但本輪沒有自動補發該狀態的 retry API，不能宣稱已完整交付物品。

## 驗證界線

完整 .NET 回歸 707 項通過，其中本輪核心定向 14 項、Host wire 2 項；另有獨立獎勵 oracle 6 項通過。三玩家實際 TCP 的 7 項檢查涵蓋邀請拒絕／接受、隊長權限與名單、A/B 隊總傷害 24 超過最後一擊 C 的 10、A/B 各得完整 EXP50 與私人藥水、零輸出離線隊員補領，以及重啟後不重複結算；正式模式地面物品回歸亦通過。

兩輪 TCP 使用同一最終 Host DLL，SHA256 為 `3572276969a67c9a9f6cdaac954b597d869221ee0a74a7b059a13d3d91b8a38f`。已檢查 S0A17 的 CP950 位元組長度、BEu16 與無 NUL，以及管理拒絕時資料不變。核心另覆蓋 13 人上限、多項獨立掉落、凍結名冊、重播、政策變更拒絕與回滾。

以上使用隔離 SQLite／協定模擬客戶端；PostgreSQL 執行期負載／併發、原生視窗、列表操作、13 人畫面及短訊息仍待實測。不把協定模擬稱為原生畫面通過。
