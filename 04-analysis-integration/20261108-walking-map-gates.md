# 步行入口與五城重建路由

2026-11-08。延續 [原生入口資料與路由權威](20261102-native-portals-and-route-authority.md)。本規格可供獨立 Server 實作，不包含私有程式或原始資源。

## 需求來源與證據界線

- **使用者需求／回報**：左側地圖藍點、游標變化是切換地圖入口；希望正常遊玩能切換地圖，技能與管理傳送亦須在線完成。
- **既有原件分析**：Basic.dat bank0 slot24 的 Portals.tbl 只有來源 MAP、X、Y，沒有目的地。格式為 LE u16 版本1、LE u32 筆數、2840組 LE i16 map/x/y，312張圖有入口。完整目的地關係仍待證，不能由鄰近圖號或小地圖顏色猜定。
- **本輪 Server 設計**：只為五城各選一組原生入口，建立明確標示的單向重建環。這不是原服路線，也不宣稱所有2840格都已能切圖。
- **驗收界線**：合成封包與真 TCP 測試不等於原生 GUI 驗收。跨圖舊 S07 地標清除、顯示標籤及連續步入體驗仍須實測。

來源身份：Basic.dat SHA256 `0da379bf6dcc58be8ff3e4865fe8fe4859ae531f4aaef386196be56123082b96`；Portals.tbl SHA256 `b63c4f07765271baf83c9a5104fafe21070e2e3ca7926aec23c17eda84047d00`。入口原生處理地址及小地圖標點演算法見前述分析。本輪沿用該證據，未新增反編譯結論。

## 可獨立實作的規則模型

每條路由有唯一 Key、Revision、來源 MapRef／來源內容版本、來源 Tiles、目的 MapRef／目的內容版本、ArrivalX/Y、Facing、顯示 Label，以及 `RoutingOrigin=server-reconstruction`。可選 RequiredLevel（預設1，1..99）、RequiredCareer、RequiredAdmissionRevision。

[可攜式五城規則資料](20261108-walking-map-gates.json)提供本輪精確內容版本與12格座標，不含私有程式、素材、金鑰或本機絕對路徑。各實作自行將已取得的 Basic.dat 路徑接入設定；此檔不承諾原服目的地。第一版限制來源與目的為不同 MapRef，尚不支援同圖傳送入口。

啟動時檢查：只接受明確啟用且承認重建路由的開發設定；讀取上述 SHA 綁定的入口表；每個來源格必須是原生入口且可站立；來源／目的內容版本必須存在。到達格必須可站立且不能是任何原生入口，避免載入後自動連跳。同一來源圖／版本／座標不可被兩條規則重複認領；不同圖間的相同座標不衝突。

上限128條規則、每條1..64格、全域256格、單一來源圖版本128格。Key限 ASCII 英數與點、連字號，最多64字；Key加Revision最多120字。Label最多60字且必須可用 CP950 string8 表示；版本必須非空、無控制字元且不超過128字。配置快照不得受呼叫端後續修改影響。

路由 Key／Revision 第一次使用即與完整規則內容綁定。相同版本改座標、條件、名稱或目的地必須拒絕，變更需新 Revision；載入 epoch 另外保存精確規則快照，防止 C35 時換一條路由。

## 權威與封包順序

1. 只在有效租約、生存、WorldReady 下，Server 接受 C33 單步移動並保存新來源位置後評估入口。位置版本須恰好+1、同一角色／圖／版本、相鄰一步，且前格在該組外、新格在該組內。重播、轉身 C11、游標與 C54 不授權切圖；重登站在入口或組內走動不重觸發。
2. 已開 NPC／教學互動視窗時不開始入口傳送。等級、職業與入學條件不符時，只回移動 ACK 和提示，角色留在已接受的入口格，仍可走出。
3. 先發 S0B 移動 ACK，再 S15 目的地資料與 S14(1)。三者的加密序號須按實際發送順序連續配置。開始載入後清理來源場景投影、對話與交易，排隊舊圖移動不能更改位置。
4. 伺服器保存 pending epoch，耐久位置仍是**來源入口格**。只有期限內、同租約、相同規則、仍存活且仍符合資格的正確 C35（目的圖及結構 checksum）能原子提交目的地、到達格／面向、載入狀態與既有 outbox。失敗不得部分提交，也不得完成新手畢業或發獎。
5. 成功後沿既有 S04／S33／S08／S14(2) 等流程恢復；移動序號可依既有傳送規則重置。未確認即斷線、錯誤 checksum、逾時或舊租約都不能保存目的地；重登回最後提交的來源／目的位置。

**已知原子性邊界**：來源單步提交與建立傳送 intent 分為兩筆交易。若中間故障，角色會留在來源入口，重登不自動傳送，走出再走入可重試。這不保證每次踏入都必定產生 intent，但不會錯存尚未載入的目的地。

S07 kind13 僅提供已配置入口的 XY／名稱地標，每16格一包；其名稱不授權切圖。未配置入口保持無推測目的地。來源入口分組為 Server 的8鄰接選擇方式；原件小地圖 NW/N/NE/W 標點判斷不應被誤稱為原生 gate ID。

固定策略為 `1 → 2001 → 4001 → 6001 → 7001 → 1`，Revision `reconstructed-town-ring-v1`。各目的落點為下一城入口組旁安全格，可再走一步接續下一段；不是雙向原服配對。預設資料產生如下：

## 保存、遷移與測試入口

新增兩類耐久資料：路由 Key／Revision 與契約；傳送 epoch 與契約。既有 SQLite 第一次補表前先做一致性備份，重複啟動不重複遷移。舊有位置、技能、任務、裝備與帳號保持。PostgreSQL 實例等價與完整還原演練另驗，不能由 SQLite 測試推定。

私有開發環境提供可選入口 `tools/native-map-gates-dev.cmd`：沿用所選職業既有帳號、DB與管理金鑰，另外建立一次性的世界／角色配置覆蓋檔；後續自訂配置不覆寫。原職業測試入口不預設啟用此路由。Map6沒有原生入口；全新角色可沿開發場景既有傳送到職業城鎮，已保存其他圖的角色不強制改位置。

集中 GUI 待測：城鎮走到設定入口→自動切圖→連續五城→每次確認地圖與人物落點／BGM／衣裝→中途離線重登→載入中斷線後回來源。藍點原生入口未配置目的地時，不應冒出猜測路線。
