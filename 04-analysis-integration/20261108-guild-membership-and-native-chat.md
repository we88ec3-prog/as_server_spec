# 公會會員管理與三種原生聊天頻道

使用者要求持續開發完整Server，並把可供獨立實作者使用的規劃／分析放公開spec、程式保留私有roy。本輪補公會的可操作會員與聊天流程。**會員規則、容量、權限、邀請時效、指令、公告及保存方式都是Server重建設計**；本輪沿用既有REA原件證據，沒有新增未核對的Client封包或修改EXE／素材。

## 原件已證與尚未證

[原生聊天研究](20261108-native-chat-and-whisper.md)已沿ChatInput的0x42E52C～0x42E5C7確認公會模式2與subindex0..2；BasicString[482..484]分別是「和睦公會」「戰爭公會」「一般公會」。送出C19 kind0的target字串為 `!1`、`!2`、`!3`，各自接一個text:string8。這些不是隊伍子組；隊聊target仍是 `!!`。C19 kind1仍是本機拒收通知，不改作公會操作。

此證據只證明原生聊天輸入標記，不證明原服是否允許同時加入三類、建立條件、會長權限或戰爭規則。原生GuildListDialog的完整管理／名單協定仍未知。本輪會員管理使用 `/guild` 明示Server指令，經既有C0E kind0輸入；S0A17私人提示、S0A18私人歷史顯示結果，不偽造C12／S58會員結構或新guild opcode。三個頻道沿原生C19入口，但GUI顏色／視窗、會名頭銜顯示與原件實機驗收仍待補。

## 可操作命令

`類型`為1和睦、2戰爭、3一般。重建版允許每角色在每類加入一個公會，三類彼此獨立；這不是已核原服規則。

|命令|行為／權限|
|---|---|
|`/guild create 類型 名稱`|建立並成為會長；同類型的有效公會名稱唯一|
|`/guild invite 類型 角色名稱`|會長邀請目前已登入載圖完成的角色；不直接加入|
|`/guild accept 類型`、`decline 類型`|處理自己該類型唯一有效邀請，不需複製ID|
|`/guild list 類型 [頁數]`|本人公會名、公告、每頁10名會員、會長與目前在線狀態；外人不列會員|
|`/guild notice 類型 文字`|會長保存公告；文字`-`清除。公告不對外廣播|
|`/guild leave 類型`|一般會員離會；會長有其他會員時須先轉交或解散。最後一人離開關閉公會|
|`/guild kick 類型 角色名稱`|會長移除本會其他會員，對方可離線；不能指定自己或外人|
|`/guild leader 類型 角色名稱`|會長把權限轉給本會另一會員，原會長保留一般會員資格|
|`/guild disband 類型 confirm`|會長明確解散；缺confirm只提示，不變更資料|

例如 `/guild create 3 測試公會` → `/guild invite 3 角色名稱` →對方 `/guild accept 3`；之後使用Client的一般公會頻道。全部管理指令保留私人結果，不會落到附近聊天。沒有新增創建費、EXP或物品獎勵。

公會名嚴格CP950、最多24個編碼後bytes、不能空白或含控制碼／頭尾空白；FormKC及不分大小寫的正規化只用於唯一性。公告最多255 CP950 bytes，不含控制碼。解散後釋出同類名稱，原公會ID不重用。角色可同時在三類擔任不同職位；本版只有會長／會員兩種權限，其他官階未實作。

## 邀請、權限與保存

每會最多100人，每個受邀角色每類最多一份待處理邀請，發出起60秒有效。邀請包含隨機ID、guild ID／類型、邀請者會員身份、邀請者完整World租約、受邀者完整租約及截止時間。受邀者每5秒最多查一次新邀請，收到私人提示；也可用list查詢。提示不是加入同意。任一端聊天拒收另一方，不能邀請或接受；受邀者重連後不能接受舊連線邀請。

接受時重新確認有效公會、類型、當前會長仍為原邀請者且會員身份未改、邀請者租約仍在線／載圖完成、自己未加入該類、容量、拒收關係與guild ID／revision期待。其他會員變動後仍可讀新快照再接受，不靠過期邀請快照覆寫新名單。盜用別人的邀請ID、舊會長邀請、過期／舊連線、已加入及重複接受都不能加人。

所有管理從已綁定的來源World身份推導角色，不接受Client自報會長或會員權限。先鎖來源精確租約、核已提交載圖，再用既有social／party gate序列化名單；不倒序鎖另一玩家租約。更新CAS同時綁guild ID與revision，避免離會改入別會後相同revision被誤認成同一會。每次真正加入生成新的會員身份UUID，其他會員改動不替換既有身份。

公會狀態、唯一會名、每類會員索引、邀請與來源操作收據在同一交易提交。保存、會員索引或收據故障全部回滾。每個新的正常C0E意圖由Host產生內部操作ID，不使用聊天字串hash去重，也不冒稱Client提供了nonce。同一內部ID只重播原收據，換內容重用須拒絕。每來源最多128份仍有效收據、每份保留24小時，滿額拒絕修改而不刪有效收據；期限到才回收，不是每天零點重置。

新增四個持久集合：`guilds`（ID、類型、有效正規化名稱、revision、名單／公告）、`guild_members`（角色＋類型唯一索引）、`guild_invites`（受邀角色＋類型唯一、到期）、`guild_ops`（來源＋操作ID、命令／結果／到期）。有效會名以類型＋正規化名稱唯一；關閉後名稱索引為NULL，歷史狀態保留。邀請與收據設到期索引。SQLite升級檢測四表缺失，既有含帳號的檔案先做一致性備份，再同交易建表；完整四表存在後不重複備份。單獨公會升級備份標籤pre-guild-membership-v1，舊角色／金鑰／其他社交資料不重建。Pg共用DDL與social gate順序，但本輪沒有Pg實例升級、並發或還原證據。

## 聊天與成員生命週期

三類聊天的收件者只從當下來源所屬該類guild的權威名單取得，並須有已提交、無pending載圖的當前連線。跨圖可收、外人與其他類不收。每個接收者的拒收名單排除來源，但保留來源自己的一份回音。未入會回私人提示並保持連線；`!4`等未知頻道仍不轉普通密語或附近聊天。

沿既有聊天的255 CP950 bytes、10秒最多5則、每連線256份待收、2分鐘保留與每次32份drain；三類與其他聊天共用發話額度。容量不足時整筆不投遞，不部分廣播。舊ChatChannel的Local／Whisper／Party數值與JSON保持，新類型追加；新GuildId／scope可選欄位不寫入舊非公會JSON，舊queue可讀。

每封公會queue另綁guild ID、類型、來源會員身份和接收者會員身份。領取時重新核兩方仍在相同guild、相同會員身份以及拒收政策。離會、踢除、解散、重新建立同名會或離會後重加入，均不能讓舊訊息恢復可讀。單純換會長／改公告不改會員身份。接收者新World租約不繼承舊連線queue；已合法接受的訊息可在來源斷線後、會員仍有效且未到期時交付。這是重建投遞政策，不宣稱原服離線公會聊天或exactly-once；dequeue後至TCP寫出前崩潰仍可能遺失，已寫到網路的內容不能撤回。

名單與公告跨重連／自有Server重啟保存；在線狀態按當前有效租約查詢，會員不因正常斷線被踢除。公會成員名單中的在線查詢不是好友系統的「可聯絡」承諾。公會戰對戰、會館、倉庫、聯盟、官階、原版建會條件、頭頂會名及原生GuildListDialog同步均未完成。
