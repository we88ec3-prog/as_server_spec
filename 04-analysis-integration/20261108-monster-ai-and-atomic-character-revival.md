# 怪物追擊、玩家受傷與同圖復活

本文件是可獨立實作的 Server 契約。目標來源為使用者要求持續開發 Server；本輪具體 AI 數值、被動反擊及自動復活是重建設計，並非反編譯得到的原服規則。原生封包依據另見 [原生步進與死亡分析](20261108-native-monster-steps-player-death-and-respawn.md)。

## 範圍及預設

本輪將既有共用訓練怪物接上追擊、反擊、玩家 HP 扣除、死亡禁移動與同圖復活。僅作用於已設定且通過資源驗證的戰鬥地圖，不表示全地圖怪物配置已完成，也不表示完整多人戰鬥同步已完成。

| 設定 | 重建預設 | 意義 |
|---|---:|---|
| AI 開啟 | 是 | 可獨立停用；舊的合成測試內容未指定 AI 時維持靜態 |
| 主動索敵 | 否 | 被有效攻擊後反擊；避免新角色讀取歡迎提示時被主動擊殺 |
| 主動索敵距離 | 8 格 | 僅主動索敵模式使用，按八方向最大座標差 |
| 離出生點追擊界限 | 12 格 | 目標超界或失效時返家 |
| 單步間隔 | 500 ms | 每張地圖共用一次節拍 |
| 相鄰攻擊間隔 | 1000 ms | 每怪物獨立間隔 |
| 傷害 | 5 HP | 由 Server 算實際扣除，不能扣成負數 |
| 路徑搜尋上限 | 1024 節點 | 只採用已驗證地圖移動政策允許的邊，不斜穿牆角 |
| 玩家復活等待 | 5000 ms | 0 可停用；同圖原設定出生點 |
| 復活 HP | 最大 HP 的 10%，向上取整且至少 1 | 依既有成長政策；MP/SP/BP 保留，死亡不增加回復 |

本輪無死亡經驗懲罰、無原服掉裝推論。自動資源回復不復活死亡角色。怪物空間狀態與 AI 政策分開固定版本；不得為開啟 AI 而改寫既有怪物生命／命中契約。改變已固定的 AI 政策需要顯式遷移或獨立測試環境。

## 權威狀態與交易

1. 每個怪物出生點保存生命序號、HP、物件引用與版本；AI 保存同一生命的實際座標、面向、目標的完整連線租約、狀態及最後攻擊時間。所有攻擊方式都讀取這個實際座標，不能仍用靜態出生點判定範圍。
2. 每張地圖／內容版本只有一個下一節拍時間與事件序號。第二名觀察者同時輪詢不能讓怪物加速；離線時間不補算大量追擊或傷害。
3. 被動模式依有效命中的怪物版本選擇攻擊者，不能以相同時間戳猜測先後。目標須在線、已完成載圖、同圖同版本、存活且在界限內。死亡、離線、換租約或離圖後，不再沿用舊目標。
4. 同一節拍先依角色 ID 固定順序鎖定參與者，再鎖地圖／怪物共用狀態。玩家攻擊與 AI 使用相容的鎖定順序，避免兩名觀察者反向鎖定造成死鎖。
5. 傷害、資源版本、死亡判定及持久事件同一交易提交。事件保存攻擊者快照、受害者完整租約、實扣 HP 與提交後狀態；各 Client 使用獨立單調游標讀取，不能由第一個觀察者消耗其他人的事件。
6. 每次實際步進記錄前後座標及版本，才能逐步驗證碰撞；只比較兩次抽樣終點不足以證明未穿牆。怪物死亡停止行動，重生後使用新生命引用並重置 AI 到出生點。

持久化至少需要下列五類紀錄；名稱可由各 Server 自行選擇，主鍵及防重語意必須保留。新增到已有角色的 SQLite 資料庫前先建立一致備份；第二次啟動不因同樣的表再次備份或重授物品。

| 紀錄 | 主鍵／唯一性 | 必要內容 |
|---|---|---|
| AI 地圖時鐘 | map＋內容版本 | 完整 AI 政策、下次節拍時間、最新事件序號 |
| AI 怪物狀態 | map＋內容版本＋出生點 | 生命序號、實際座標面向、Idle/Pursue/Return/Dead、完整目標租約、最後攻擊時間及已處理命中版本 |
| 傷害事件 | map＋內容版本＋事件序號，事件 ID 唯一 | 不可變攻擊者／受害者快照、實扣傷害、結果資源、致死旗標與時間 |
| 步進審計 | map＋內容版本＋出生點＋生命序號＋怪物版本 | 前後座標、方向、提交時間；不同生命的重置不是普通一步 |
| 復活收據 | 角色＋操作 ID | 完整預期命令、結果位置／能力及提交時間；同 ID 異內容拒絕 |

目前重建場景將鎖定候選玩家數限制為 128，事件每頁最多 256，Host 每次讀 128。這些是明示開發界限，不是原服容量；超界不得部分模擬後宣稱完整多人支援。

## 斷線與玩家死亡

TCP EOF／錯誤／逾時收尾須刪除該角色的精確 account、generation、connection 租約，不刪除角色、位置或進度。舊連線的延後清理不得影響替代連線。否則在線表殘留會讓 AI 攻擊已關閉遊戲的玩家。

死亡後，位置提交交易直接拒絕移動及轉向。Host 回送權威位置的拒絕 ACK／面向，不能將正常的死亡限制當成封包錯誤斷線。普通攻擊與技能、藥水依死亡狀態拒絕；墓碑只是呈現，不是死亡權威。

復活須在單一交易內核對完整租約、已提交載圖、預期位置版本及能力版本，再同時提交復活 HP、同圖出生位置、位置版本、收據與事件。過期租約、不同地圖、不可站立出生點或版本不符不得部分提交；相同操作識別重播只回舊收據，不再復活或把角色拉回。

## 原生呈現

| 情境 | 封包與限制 |
|---|---|
| 怪物一步移動 | S0C 使用**舊起點**及方向，Client 自行前進一格；填新終點會多走一格 |
| 觀察者漏掉多步 | 移除再依權威位置生成，不由兩個終點編造穿牆路徑 |
| 怪物命中自己 | S13 的攻擊者為怪物引用、受害者為當前 Client 的自己引用；接 S08 權威 HP |
| 玩家死亡 | S08 顯示 HP0，S1A motion3 顯示目前兩套基礎角色的墓碑；不向自己送 S5F |
| 同圖復活 | 原子提交後 S05 重建自己、S04 位置／視角、S33 外觀、S08 資源、S1A motion0 |

同圖復活不送 S15、不開新載圖 epoch、不要求新 C35。C35 只有地圖與 checksum，不能區別同圖新舊 epoch，故不拿重複 C35 宣稱本次復活已被畫面確認。各原生 handler 有靜態依據；上述組合的墓碑與復活畫面仍需原生 GUI 驗收。

目前試驗 Client 的自己引用為 1；不可把另一受害者的事件投影成自己的傷害。完整多人角色引用配置、旁觀其他玩家受傷動畫、空地圖常駐模擬、掉落與仇恨隊伍規則仍是後續工作。

## 驗證與待測

隔離封包測試已驗證 S0C 舊起點、怪物→自己傷害、死亡禁移動不斷線，以及無 C35 的復活提交及自己重建序列。最終完整 .NET 回歸 672 項通過；其中本輪新增導覽 4 項、AI／死亡／復活持久化 13 項及 Host 封包／斷線 2 項。另有 6 項獨立地圖步進 oracle 測試通過。資料庫執行驗證使用隔離 SQLite；未宣稱完成 PostgreSQL 實機併發壓力測試。原生 Client 尚未驗收，不以這些自動測試替代。

最終隔離 Host 的 SHA256 為 `bdba8c0c553a18b7f149b7b29316de579bc1d7a0410ae6f23144eddfb814c180`。兩名不同帳號觀察同一怪物的實際 TCP 驗證已通過：逐步繞過原 Map6 障礙、S0C 使用舊起點、攻擊不因觀察者數加速；關閉受害者連線後停止對該租約扣血，兩名斷線後在線租約數為 0。另驗被動模式未被命中不主動攻擊，受到有效攻擊後反擊。

同版致死 TCP 驗證得到 HP0、墓碑 motion3、拒絕移動 ACK、無自己的 S5F；約 5.187 秒後重建自己並復活，無 S15/S14 新載圖。已投影至 Client 的有效 HP 藥水在死亡期間回覆 Dead，三瓶數量及物品版本均不變；本次藥水由受限隔離測試授物取得，不能說成已通過本輪購買後實戰回血驗收。復活後 C0B 回登入再登入，資源 JSON 與位置保留。跨圖失目標、同版 Server 重啟及原生畫面不借用這次通過紀錄；尚待各自驗證。

集中實測應包含：先不攻擊確認被動怪物不主動傷害；攻擊後追擊並受傷；喝藥回血；離線不再被追攻；死亡後墓碑且不能移動；等待復活；重新登入核對位置與 HP。不要使用原角色環境改成高傷害進行壓力測試。
