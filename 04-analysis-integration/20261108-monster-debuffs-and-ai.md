# 怪物減益：減速、衰弱與定身

使用者要求所有職業技能能實際生效，並在測試期間持續開發。這是需求來源；以下技能名稱、成本、時間、疊加及取消規則均為 **Server 重建設計**，不是從 EXE 還原的原服設定。沿用既有 S62 指定目標列、C65 施放、S1A 動作、S0A 私人提示與怪物 AI 呈現；本輪沒有新增原生封包或素材證據，也沒有修改原始 Client。

## 目錄及操作

內建目錄升至 `reconstructed-career-skills-v8-monster-debuffs`，共37項。只有完整匹配內建 v1..v7 的目錄才自動補新技能，自訂目錄不暗改。舊定義的 canonical JSON、技能 key、Skill／Spell 庫、位置、熟練及冷卻保持原有身份。新增可選 Debuff 欄位，null 不序列化，避免相同舊 revision 的內容改變。

|技能|職業／庫|射程|成本／冷卻|實際效果|
|---|---|---|---|---|
|mage.slow／重建遲緩|魔法師／Spell kind0|兩軸各≤6格|MP8／3000ms|10000ms內移動速度降低50%，不改攻擊頻率|
|thief.weaken／重建衰弱|盜賊／Skill kind1|相鄰，兩軸各≤1格|SP8／3000ms|10000ms內原始攻擊傷害降低50%|
|bard.root／重建束縛|吟遊詩人／Spell kind0|兩軸各≤6格|MP10／5000ms|5000ms不能移動，仍可原地攻擊|

三者均 Lv1、rank1，不直接造成傷害。吟遊詩人的新 Spell 不搬動既有 Skill。使用新 S62 mode2 列，拖到快捷列後按鍵再選怪物；C0E 文字前導不扣費，已發行技能身份匹配的六 byte C65 才結算。既有租約、位置、已投影怪物生命、可信地圖射程／視線、資源與冷卻檢查照常執行；NPC、玩家、過期或未投影 ref 不當成怪物目標。

僅配置 MonsterAi 的戰鬥場景可施放。沒有 AI 時回覆 NoChange，不扣資源、不建立只顯示卻無實效的狀態。不是宣稱所有地圖已有完整怪物配置。

## 有界狀態與生命隔離

唯一鍵為 mapRef／contentRevision／spawnKey／減益種類。同一種類最後一次成功施放取代來源、強度與截止時間，不相加、不退款；三種可同時存在。每圖既有最多32隻怪物，因此最多96個減益格，不能以任意技能 key 膨脹資料。重播原操作收據不刷新時間、不重複扣費或增加熟練。

通用政策限制：持續1000..60000ms、射程1..6格；Slow／Weakness 強度1..75%；Root 強度固定100%、持續最多10000ms。已接受的效果採施放時政策快照。之後技能目錄變更不自行重算舊效果，與持續傷害另有目錄比對取消的契約不同；AI revision 不匹配則取消，AI 場景仍禁止未遷移的政策暗換。

每格記錄來源完整 World 租約、角色生命代次、原始地圖及位置、技能／目錄／AI revision、怪物生命代次、施放 actorVersion、政策與 UTC 起訖。來源須仍在同一已載入地圖、相同連線／generation／生命且存活。死亡、斷線或新租約、開始切圖、怪物死亡／重生、到期均不繼續；開始切圖的取消與切圖意圖同交易，失敗回滾不提前丟失效果。Server 空圖時不宣稱有獨立背景清理，下一次有效觀察才清理殘留。

## 真正影響 AI

Slow 使用 `ceil(baseStepMilliseconds × 100 / (100-percent))` 作移動間隔。以該怪物同一生命最後實際移動的提交時間判斷能否再走；首次沒有移動紀錄可立即一步。原本500ms步進，在50%減速下至少1000ms一步。延遲不追趕補步，到期即回原步進政策；不永久改場景 AI 設定，不延長攻擊間隔。這是 Server 移動頻率，未宣稱 Client 每一步動畫播放速度也改變。

Weakness 先計算 `max(1, floor(baseDamage × (100-percent)/100))`，再套用玩家裝備減傷。原始5降為2，原始1仍為1。對實際 HP、死亡、持久攻擊事件及狀態同步生效，不只是描述文字。

Root 略過追擊／返家的移動分支，保留腦狀態及目標；相鄰且攻擊冷卻已到時仍可轉向及攻擊。到期後依既有 AI 恢復追擊／返家，不做延遲補打。

減益會提高怪物 actorVersion 一次，HP不變，也不插入假的正傷害 hit。被動怪物反擊比較「真傷害」與「成功減益」的最新版本，最新有效來源勝出；不依相同時間戳猜順序。沒有減益傷害、EXP、擊殺任務或掉落獎勵，也不讓無傷害施法搶到傷害歸屬。

AI 維持角色ID排序的玩家租約／狀態鎖，再取得該圖共享戰鬥 profile 鎖。減益只讀這批已鎖定的當前玩家快照，不握 profile 後回頭鎖另一施法者。施放沿來源→profile→目標／效果→最後共同呈現鎖；清理限目前已鎖定地圖，避免跨圖清理鎖反轉。這是實作鎖順，PostgreSQL 實例的併發死鎖驗證仍待進行。

## 原子性、保存與呈現

一次施放的 MP／SP、熟練、冷卻、操作收據、怪物版本、減益格與共同施放動作在同一交易。任一步失敗全部回滾。SQLite 舊庫缺減益表時先做一致性備份，再同交易建表及索引；單獨缺本表的備份標記為 pre-monster-debuffs-v1。既有帳號、角色及金鑰不重置；本輪只用拋棄式環境，不操作使用者正在測試的 DB。完整還原演練及 PostgreSQL 升級另待驗證。

可獨立實作的資料模型為單一 monster_debuffs 表：圖／內容版本／spawn／kind 唯一鍵，怪物生命、來源角色／generation／connection、expiresTicks及效果快照；另有來源索引與每圖到期索引。不是必須使用私有程式的 table prefix 或特定語言物件格式。

本人成功後播放一次既有 S1A4 動作並收到 S0A kind17 成功／期限提示；旁觀者經共同動作事件播放一次。沒有傷害便不造 S13 數字或 MISS，不套未知永久特效、狀態旗標或圖示。持續效果由實際怪物動作與傷害反映。原版具名減益圖像、音效及圖示尚未還原。
