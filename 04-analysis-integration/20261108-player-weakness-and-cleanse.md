# 角色衰弱與指定淨化

使用者要求各職業技能實際生效，並在實測期間持續開發。原先只有[怪物減益](20261108-monster-debuffs-and-ai.md)，沒有角色負面狀態可供聖職者解除；本輪補上怪物命中造成角色衰弱，以及指定自己／隊友的淨化。**名稱、機率、數值、時間、效果範圍與權限均為 Server 重建設計**，不是已還原的原服技能。沒有修改原始 Client 或資產，沒有新增猜測封包或狀態圖示。

## 可選怪物規則

MonsterAi 新增可選 Weakening 政策，預設 null／停用；原有 AI 的 canonical JSON 及規則保持原樣。啟用後，怪物每次成功造成真實命中且目標仍存活時，100%施加一次角色衰弱。強度1..75%、持續1000..60000ms，沒有機率擲骰。獨立開發場景使用50%／10000ms、每4000ms攻擊1HP；這是低傷害的測試政策，不代表摩斯的原版能力。

同一角色只有一個衰弱格，最新怪物命中取代強度、來源與期限，不相加、不挑最強。記錄開始／截止UTC、角色生命代次、來源地圖／內容revision、spawn key及怪物生命，來源只供稽核，不能憑此取得操作權限。來源怪物後續死亡、玩家離圖或重新連線不提前解除；沿用原本 UTC 截止時間，不在離線時停表。角色死亡、生命代次不符、到期或淨化才清除。這與怪物減益的來源斷線取消政策不同。

衰弱先取既有普攻／技能、正向buff及裝備傷害公式，再乘 `(100-percent)/100`，向下取整、最低1。普通攻擊及攻擊技能共用此修正；不減少治療、資源恢復或正向buff，不修改永久分配能力、HP／MP／SP上限。例：普攻8在50%衰弱下為4，傷害1仍為1。已施放持續傷害沿原本施放時快照，不因之後衰弱或淨化重算；施放當下若衰弱，快照已包含減傷。

怪物傷害、衰弱、攻擊冷卻、狀態操作收據及共同攻擊事件同交易提交。事件或狀態寫入失敗時，不留下只有狀態或只有扣血的一半結果。死亡的命中不建立新衰弱。下一次受控狀態讀取會清理死亡／到期／舊生命的格；不宣稱離線有背景掃描。

## 聖職者技能

內建目錄 `reconstructed-career-skills-v9-ailment-cleansing` 共38項。只有完整符合內建v1..v8的目錄才補技能，自訂內容不暗改。舊技能定義JSON、身份、Skill／Spell庫、位置、熟練及冷卻保留；新增 `cleric.cleanse`／重建淨化，Spell kind0、Lv1 rank1、MP6、SP0、冷卻3000ms。

沿[指定治療的原格式入口](20261108-targeted-healing-and-skill-inventories.md)，S62 mode2列選擇目標，C0E文字只作前導；匹配已發行技能的六byte C65才結算。可指定自己ref1或兩軸各≤6格的同隊生存Human。Host先確認已投影的當前租約／生命／位置及可信地圖施法視線；Store再核隊伍、穩定人物ref、完整租約與位置版本。單純知道一個ref不能授權，NPC、怪物、非隊友、過期租約／生命／位置、未投影、阻擋、跨圖與死亡角色均拒絕。

有衰弱時才扣MP6、開始3秒冷卻及加一次熟練，清掉該格；不回血、不清除正向自身／隊伍buff，也不解除其他未實作的異常。滿HP仍可淨化。沒有衰弱回NoChange，不扣費、不加熟練；若技能本來還在冷卻，優先回CoolingDown，同樣不扣費。資源不足或非法目標不移除狀態。

來源與所選目標完整租約按角色ID排序鎖定，再讀隊伍及當前目標狀態；不在已持隊伍鎖時回頭鎖另一角色。清除、來源MP／技能進度／冷卻、操作收據與共同施法動作同交易提交，自身淨化不能被最後來源狀態保存覆蓋。兩名聖職者同時淨化同一格，只先成功的一方扣費；另一方讀到已清除，回NoChange。重播舊收據不再次清掉之後新施加的衰弱，不能以舊操作解除新效果。淨化直接原子修改已鎖定目標，不借用延遲治療投遞佇列。

## 保存與呈現

角色狀態新增可選 Weakness 快照，null不寫JSON；舊狀態不需要全庫改寫，也沒有新增資料表或自動重置帳號／金鑰。首次被施加時才隨正常遊戲交易保存欄位。舊AI政策新增可選Weakening，null亦不寫JSON，因此相同舊revision不因新增功能而變動內容。

玩家收到S0A kind17私人提示：衰弱造成的傷害降低百分比，以及解除提示。同百分比被怪物刷新不反覆刷提示；地圖重建／同Client重新登入時重建目前提示狀態。淨化成功沿既有S1A4播放本人／旁觀者施法動作，當前來源收到成功訊息；目標下次自己輪詢收到解除提示。本人淨化在技能回覆就可立即收到成功與解除兩個提示，下一輪不重複。無假傷害S13、MISS、未知S2C圖示或具名特效；正向buff投影仍獨立保留。

## 設定與集中待測

既有環境預設不開此怪物規則。獨立實作者可明示設定：

```json
{
  "MonsterAi": {
    "Enabled": true,
    "Revision": "your-new-monster-ai-weakening-v1",
    "Weakening": { "Enabled": true, "Percent": 50, "DurationMilliseconds": 10000 }
  }
}
```

設定位於既有 TrainingCombat 節點下。啟用Weakening必須有啟用的AI及顯式revision；已釘選場景不能只修改revision就熱切換整組AI，必須新場景／獨立DB或明示政策遷移。既有玩家環境不暗換AI。本地另備獨立固定開發環境供稍後實測，首次才設定密碼／金鑰，後續重用；原角色及其他開發環境保留。

原生集中待測：怪物命中→收到角色衰弱提示→比較普攻／攻擊魔法傷害→遠離怪物避免刷新→淨化自己／隊友→確認傷害恢復且正向buff仍在→等10秒到期／死亡復活／同Client重登。淨化Spell須重新拖到快捷列，按快捷鍵再點選自己或隊友。敵人新的命中可合法再次施加，不能把再次被打誤認為淨化失效。
