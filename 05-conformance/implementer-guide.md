# 獨立Server實作與相容性驗收

## 最小起步

取得相符Client（本repo不附原始遊戲）；實作transport.md的binary/table0 profile；接上登入狀態機；依SCN-001初始化世界，再做自身移動與外觀。packets.json標partial的項目必須補規格，或在實作支援表列明限制，不能以作者私有原型作唯一依賴。

vectors.json是合成／固定協定字節，不包含實際帳密、token或遊戲資產。它們只驗證各自命名的層級：body向量不是整條線上封包，frame向量也不等於已還原所有遊戲規則。

共用測試分層：CT的codec／body固定向量 → SCN的狀態機／錯誤分支 → 兩客戶端互通 → 原Client人工驗收 → 重送／中斷／重啟 → 負載。新增功能必須補正常與失敗情境。

每個Server發布自己的實作清單：實作名稱／版本、Client SHA、規格版本、profile、支援R/PKT/SCN、通過CT、人工驗收日期、已知偏差、自訂規則。可通過單人profile，不能因此自稱完整原服還原或支援所有Client版本。

相容性測試應檢查外部行為，不限定作者的類別、資料表、函式名或程式語言。不要靠多抄一份私有程式輸出當作獨立測試。私有開發區可有額外測試，但共同必需規則和向量應回饋至本repo。
