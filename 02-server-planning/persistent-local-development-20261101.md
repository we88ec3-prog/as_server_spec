# 持續開發與一次性測試分離

**使用者需求**：不要每次啟動都重產金鑰／重新設定測試帳號；需要時才重產。
此需求源自實際操作回饋，不是遊戲 EXE 分析所得。

既有規格要求 Admin key 獨立於4～8字遊戲密碼、至少32字，沒有規定每次
啟動都輪替。每輪新DB／隨機key／埠是先前隔離測試工具的設計選擇，不可
當成正常玩家登入或營運要求。此處更正操作流程，保留隔離回歸測試用途。

## 行為合約

- 持續開發環境第一次設定遊戲密碼、建立帳號與穩定埠／Admin key；後續
  重啟保留帳號、角色、位置、教學進度及管理金鑰，不能覆寫既有密碼。
- Server運行時可反覆啟動Client，不需再啟動另一個Server。既有角色走
  登入UI；尚無角色才走創角UI。程式更新時重啟Server，不等於資料重置。
- 管理金鑰只存在不受Git追蹤的本機設定；不寫Client啟動參數、公開文件、
  session metadata或操作日誌。啟動器不另存玩家明文密碼。
- 手動輪替只能在該環境停止時執行；更換管理key不刪DB、角色或進度。
  拒絕重複啟動及占用埠，不擅自結束既有程序。損壞／不匹配設定報錯並保留。
- 每次玩家登入的短效transfer ticket與連線狀態仍由Server自動產生、驗證及
  消費；與穩定Admin key不同，不能為省操作改成永久共用登入票證。

私有實作已提供持續開發入口，原一次性trial入口保留。真實隔離程序驗證
跨重啟帳號／角色／位置／key／埠保留、無重複設定密碼、重複啟動拒絕、
明示輪替後舊key失效而資料保留。這是本機開發工具驗證，不宣稱外網營運、
多人管理或完整新手教學已完成。
